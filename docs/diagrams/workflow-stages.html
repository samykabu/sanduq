Managed Workflow stages and what sends work back

The managed Workflow runs one feature from Scope to a pull request, one claimed stage at a time. The left column names the command or extension that does each stage's work: Workflow for Scope and Clarify, Spec Kit for Specify, Plan, Tasks, Analyze and Execute, Memory at Specify and Analyze, Assure and User Manual for the selected QA and manual stages, Workflow runtime stages for Verify, Review and Ready, PR for the pull request and its review feedback, and Memory and User Manual again after merge. Seven numbered paths send work back: Clarify waits for answers on the issue; Analyze returns a blocking gap to Plan; a spec or plan edited mid-build makes revalidate-upstream re-record the stale stages; failed checks and blocking review findings return to Execute; failed CI and PR review comments are fixed on the branch and revalidate Verify, Review and Ready; and a change after Verify revalidates Verify, Review and Ready.
