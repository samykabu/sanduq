## Working rules (learned)

- Python: `uv run --no-project --python 3.11 --with pyyaml --with packaging --with jsonschema python`. Run suites with
  `python -m unittest discover -s extensions/<id>/tests -q` (not `-t .`). The Microsoft Store python fails about 19
  workflow tests and many memory tests on this machine.
- Known machine-only failures: three `test_install` dangling link/junction rollback tests (pass on CI).
- Never run `git stash`, `checkout`, `reset` or `clean` in a tree other agents use. Agents edit only owned files;
  the orchestrator commits per stream.
- Vendored files (`vendor.lock.json`, `vendor.py check`) change upstream in sanduq-skills first: PR, CI, merge, tag
  `<bundle>-vX.Y.Z` on the merge commit, wait for the release run, then `vendor.py update --source ../sanduq-skills`.
- Release: `release.py bump <id> <version>` once per extension (one pair per call); preset versions by hand; extension
  changelog headings `## [X.Y.Z] - date`; root CHANGELOG heading ends with ` (pending release)`; set
  `pending-releases.json` status `ready`; `check_docs.py` must pass. Merge, then watch main CI and the "Release
  extensions" run; check every job's conclusion, not a watcher's exit code (`gh run watch` can exit early).
- Measure on a quiet machine and repeat timing in alternating order; the first run after a cold start is inflated.
- Live runs: `claude -p "<slash command>" --output-format stream-json --verbose --permission-mode bypassPermissions
  --strict-mcp-config` with the parent's `CLAUDE*` variables unset; back up `.specify/extensions/project/config.json`
  before `specify extension add --force`; check `gh api rate_limit` first.
- Codex: `codex exec -m gpt-6.1-sol --sandbox read-only -C <worktree> -o <file> - < prompt.md`.
