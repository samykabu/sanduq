Verdict

On 19 October you kept every id and display name. One day and two releases later, nothing new makes a rename worth it. The catalogs have no new collisions. Spec Kit upstream still has no way to alias or migrate an extension id, and the cost of a rename has not changed. Workflow 1.16.0 added a project-sync wrapper, but Project still does every board write, so no extension's purpose has drifted (naming §1, §2).

The review found three descriptions that say the wrong thing, and these get fixed whatever you choose. Project's description promises one sub-issue per task, but in managed projects Workflow creates those instead (project_sync.py:461-463). workflow.finalize and pr.generate both answer to “open the PR”. workflow.status answers to “checking progress”, as progress.status does.

This round also reviewed all 47 command names one by one, for the first time. 37 fit and 10 are weak, but none would mislead a user badly enough to pay for a migration. The weakest group is Memory's: run archives, session processes pending archives, and prepare queues (naming §6).

On structure, the extensions overlap by design: Workflow decides when a step runs, and the extension does the work. In managed projects 13 of the 22 manifest hooks are already switched off. Every merge would cost a product that people install on its own, and Scope would also lose its MIT license, all to save one package. So no merges are recommended. One real duplication is worth removing: Memory's session and prepare hooks repeat what Workflow's handoff already does (structure §3 O3, round 3's PM6).

Command names

A renamed command keeps its old name as a Spec Kit alias for the support window (two minor releases, or until the next major, whichever is later). Each alias adds one skill or command file per host and some catalog text.

Migration paths

The recommended set renames nothing. Its only change for installed projects is two hook flags, set by reconcile during the normal upgrade. The paths below apply to whichever other cards you choose, and the page shows only the ones your selection needs.

What Codex changed

  • Memory hooks (D3) became one gated migration. Memory's approval hash covers the hooks’ enabled: line and does not bind the event at all, Memory's installer re-enables disabled hooks, and Spec Kit itself re-creates entries enabled. Done in the wrong order, automatic archiving stops silently or the next upgrade fails. The sequence is below.
  • The forwarder tests are not all deleted. 35 of them test reporting modes and wiring that stay. Progress’s old v2 output gets a deprecation notice only, because older installed Workflow still asks for it.
  • The shared remote parser goes into Scope too, with one way of reading the origin, so Scope’s four rejected remote forms and its look-alike binding are fixed in the same change.
  • New defect: Project resets a malformed state file to empty and can then create duplicate task issues. It now refuses and recovers.
  • Moved to defer: splitting workflow.py, the package-hash and path caches (they weaken drift and containment checks), the shared GitHub transport, wholesale overlay replacement and the Project init rewrite.

Items

Untick an item to leave it out, or tick a deferred one to pull it in. Your choices are saved with the approval.

Order for the Memory hook change (D3)

  1. Reconcile accepts a fresh re-registration of a hook Workflow owns, and still refuses an entry someone edited (W10).
  2. Memory’s approval hash binds each hook’s event, command, condition and priority, and leaves out enabled: only for the two hooks Workflow takes over. A hook block it cannot parse is refused, not skipped.
  3. Memory’s installer keeps an existing enabled: false.
  4. The Workflow runtime runs the session check inside the claim, under the lock it already holds, and stops on every blocked result. session.md and prepare.md get their managed branches.
  5. Upgrade and doctor refuse while an archive run is active. Queued entries keep their approval; nothing is re-stamped.
  6. Only then does reconcile switch the two hooks off in managed projects.
  7. Gate: a scripted lifecycle on the pinned Spec Kit (Memory installed before and after Workflow, re-init, update, restore, automatic mode off, an interrupted archive) and one live managed run counted from its transcript.

Releases

All nine extensions and the scope-gate preset change; scope-brainstorm and the workflow preset get text fixes. Upstream in sanduq-skills: dev-tools (the portable manual init fix, quiet builds, a template removal) and illustration-tools (import checks, a text fix, the hand-drawn route), then vendored. One item needs you rather than code: keeping Python in the self-hosted runners’ tool cache (X14) is a cluster setting, worth 10 to 16 runner-minutes per CI run.

Risks to watch

  1. Memory migration integrity. Renewing approval can switch automation off, strand queued entries and block prepared archives.
  2. Partial upgrades. Packages updated one at a time can re-enable hooks or drop a schema an older Workflow still needs.
  3. Remote writes before local completion. Scope and Project write to GitHub first; a retry must recover what exists, not create it again.
