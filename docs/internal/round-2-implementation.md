## Shared contracts

- **Descriptions.** For every `provides.commands[]` of the seven extensions, the command file's
  frontmatter `description` and the `extension.yml` description are the same string: third person,
  what first, a "Use when" clause, one or two quoted trigger phrases, under 300 characters. S1 adds the
  equality check to `check_docs.py` for exactly these seven extension ids; every stream makes its
  own extension pass it. `docs/reference/commands.md` is regenerated by the orchestrator.
- **Freshness delta (AS4, S2).** `sanduq_freshness.record_or_status` adds `changed_inputs` and
  `changed_outputs` (sorted repository-relative paths; new, changed or deleted) to the status result
  when `current` is false; `--summary` appends `changed_inputs=N changed_outputs=M`. Other keys and
  exit codes unchanged. S1 and S2 word their rerun steps against these names.
- **Illustrate type index (IL3).** Upstream adds `references/type-index.md` (one line per type and
  variant: name, when to use it, its `type-*.md`). Consumers (S1 assure commands, S2
  `user-manual.analyze.md`, S3 `pr.generate.md` through `pr-diagram-recipe.md`, S5
  `scope/references/illustrate-plan.md`) say: read `.specify/extensions/illustrate/skill/references/type-index.md`,
  choose the type, read its `type-*.md`, and read `SKILL.md` only when the diagram is created outside
  that recipe. Nothing else in a consumer lists diagram types.
- **Policy keys** (`.specify/workflow.yml`, validated by S4 in `workflow.py validate_policy`; readers
  parse the file with PyYAML and treat a missing key as the default):
  `progress: {hook_wiring: speckit | native (default speckit), post_tool_matcher: "" (default, every tool)}`,
  `illustrate: {hooks: {self_check: false}}`. Outside workflow.yml: `scan.exclude` in
  `assure-config.yml` (default the eleven folders in `analyze.md` today), `lifecycle.impact_scope:
  all | evidence` in `User-Manual/manual.yml` (default all), `guard_hooks: false` in memory's
  `archive-policy.json`.
- **PJ1 claim field.** `claim` prints `project_sync: {"phase": "<phase>", "command": "<line>"}` where
  the line is the host shell's sync script with `--phase <phase> --summary`, or `project_sync: false`.
- **PR1 receipt fragment.** `pr_publish.py` prints exactly the fields `workflow.py` verifies for the
  PR receipt (`pr_url`, `pr_body_file`, `pr_lint_file`, `pr_body_sha256`, `evidence`); S3 reads the
  verification code before naming them.
- **Hooks.** New hook files use the `hooks/hooks.json` shape the workflow extension already ships
  (same file for both hosts); memory and illustrate hook commands exit 0 at once when their key is off.
