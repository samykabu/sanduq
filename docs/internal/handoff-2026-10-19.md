## Working rules learned the hard way

- Several agents share one working tree: never run `git stash`, `git checkout -- <path>`,
  `git reset`, `git clean` or `git switch` in the shared tree. Give each agent disjoint file
  ownership and one notes file section. Commit per stream yourself after review.
- Run workflow tests from their folder, because they import each other as siblings:
  `cd extensions/workflow/tests && python -m unittest test_x test_y -q`; whole suites with
  `python -m unittest discover -s extensions/<ext>/tests -q` (the workflow suite takes 25 to 35
  minutes; split it in two halves). On this machine 19 workflow tests and 1 scope test fail
  regardless of the change (`test_verification_plan`, `test_execution_tools`, `test_memory_handoff`:
  hashing the Microsoft Store `python.exe`; `test_plan.RealIllustrateTests`: PNG export without
  Chromium). They pass on CI. Everything else must be green.
- Gates to run before any commit: `python extensions/scripts/check_docs.py` (user pages must not
  link into `docs/internal`; `--write` regenerates `docs/reference/hooks.md` and `commands.md`),
  `python extensions/scripts/validate_skills.py extensions presets`, `git diff --check`. Check a
  command's exit code directly, not through `| tail`.
- CI runs on two self-hosted runners (`homek8-general`), one run per push; cancel superseded runs
  with `gh run cancel`. Before merging, read every job's conclusion with
  `gh run view <id> --json jobs`; do not trust the exit code of `gh run watch`. PR CI and main CI
  both take about 25 minutes.
- Release: bump `extension.yml`, write the package `CHANGELOG.md` entry and a root `CHANGELOG.md`
  line, keep `catalog.json` untouched, set `extensions/pending-releases.json` to
  `{"versions": {...}, "status": "ready"}` in the PR, merge to main; `release-extensions.yml` runs
  after a green main CI, publishes `<id>-vX.Y.Z` assets, promotes both catalogs and commits. Verify
  with `gh release list` and the catalog on main. `python extensions/scripts/release.py prepare
  --development` is the local dry run.
- Pinned Spec Kit for CI is in `extensions/workflow/dependencies.json` (`tested_spec_kit`). The
  smoke install is `python extensions/scripts/smoke_install.py --host claude --second-host codex`.
- Vendored skill updates arrive through the `vendor-update` workflow (`gh workflow run
  vendor-update --ref main`), which opens a PR; bring it up to date with `gh pr update-branch`.
